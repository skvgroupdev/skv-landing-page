# Agent Guide — SKV Landing Page

## Project overview

`skv-landing-page` is the public SKV Group marketing website. It is a Lao-first, bilingual (Lao/English) Next.js App Router application with a main landing page, a POS product page, and a team profile page.

Stack:

- Next.js `16.1.1` with React `19.2.3`
- TypeScript in strict mode
- Tailwind CSS v4 with `@tailwindcss/postcss`
- `lucide-react` icons and selected Radix/shadcn primitives
- `next/image` for local assets
- Framer Motion for selected UI animation
- Vercel Analytics

This directory is a separate Git repository. Work from this directory for landing-page changes; do not modify `skv-pos-web` or `skv-pos-server` unless the task explicitly includes them.

## Run and validate

Run commands from `skv-landing-page/`:

```bash
npm run dev       # local development server, normally http://localhost:3000
npm run lint      # ESLint
npm run build     # production build and TypeScript/Next validation
npm run start     # serve a completed production build
```

`package-lock.json` and `pnpm-lock.yaml` are both present. Prefer npm because the project scripts and current workflow use npm. Do not regenerate or remove either lockfile as part of an unrelated UI change.

Current validation baseline: `npm run lint` has existing failures in `app/team/vongchln/page.tsx`, `components/Awards.tsx`, `components/Contact.tsx`, `components/SystemPreviewTabs.tsx`, and `components/Team.tsx` (mainly `no-explicit-any`, unescaped JSX punctuation, and unused imports). Fix these only when the task includes lint cleanup or when your changes touch the relevant code.

## Routes and entry points

- `/` — `app/page.tsx`, the bilingual SKV Group landing page.
- `/pos` — `app/pos/page.tsx`, the Lao POS product page.
- `/team/vongchln` — `app/team/vongchln/page.tsx`, the Vongvilay profile page.
- `/dam` — `app/dam/page.tsx`, currently a placeholder page.
- `/sitemap.xml` — generated by `app/sitemap.ts`.
- `/robots.txt` — generated by `app/robots.ts`.

The root landing page is a client component because it owns language and scroll state. The POS page currently uses Lao content directly and passes `content.la` to the shared navbar.

## Working conventions

1. Read the full relevant component and its parent route before editing. Keep patches small and avoid broad refactors.
2. Preserve Lao text exactly unless the request is specifically about copy or translation. When changing visible copy used in both languages, update both `en` and `la` entries in `lib/content.ts`.
3. Keep reusable marketing copy, service data, labels, and team data in `lib/content.ts`. Do not duplicate those values in multiple components.
4. Use the existing Tailwind utility style and current visual language: the home page is light/blue, while the POS and profile pages use dark premium surfaces with blue/amber accents.
5. Use `next/image` for local images under `public/`. Preserve meaningful `alt` text, responsive sizing, and `priority` only for above-the-fold images.
6. Use the `@/*` path alias when it makes imports clearer; relative imports are also used in existing files, so do not rewrite imports without a reason.
7. Treat client/server boundaries deliberately. Keep `"use client"` only in components that need state, effects, event handlers, browser APIs, or client-only libraries.
8. Keep external links safe with `target="_blank"` plus `rel="noopener noreferrer"`. Never put secrets or real service credentials in client code.
9. Contact form integration is not production-ready: `components/Contact.tsx` contains placeholder EmailJS template/public-key values and the section is currently not rendered from `app/page.tsx`. Do not enable it without explicit configuration and verification.
10. Do not invent missing requirements. If a visual, content, route, or business behavior is ambiguous, inspect related code and ask before making a product-level assumption.

## Known project details and pitfalls

- The default home language is Lao: `useState<Language>("la")` in `app/page.tsx`.
- The home page currently renders `Navbar`, `Hero`, `Partners`, `Services`, `About`, `MyCustomer`, and `Footer`. `Contact` is commented out.
- Navbar anchors include `#services`, `#about`, `#portfolio`, and `#contact`; verify that the corresponding section IDs actually exist when changing navigation.
- `lib/content.ts` contains both language copies, but some page headings and profile/POS copy remain hardcoded in components.
- Global CSS defines the font variables, dark theme tokens, glass utilities, grid/dot backgrounds, and custom animation classes. Add shared visual primitives there instead of scattering global CSS across components.
- `public/` is the source of truth for site imagery. Check existing assets before adding duplicates.
- `next.config.ts` is intentionally minimal and currently has no custom image remote patterns.
- The `components/ui/` directory contains generated-style primitives; prefer composing them over introducing a new UI dependency.

## Change checklist

Before editing:

- Identify the route and all components/data/assets it uses.
- Check the current Git diff with `git status --short` so unrelated work is preserved.
- Confirm whether the change affects Lao, English, or both.

After editing:

- Run `npm run lint` for every code change and report pre-existing failures separately from new failures.
- Run `npm run build` for route, metadata, TypeScript, layout, or larger UI changes.
- Check responsive behavior at mobile and desktop widths when changing layout or navigation.
- Verify image paths, anchor targets, keyboard focus, button/link semantics, and Lao text rendering.
- Summarize changed files and validation results; do not claim a check passed if it was not run.

## Definition of done

A landing-page change is complete when the requested behavior is implemented with the existing patterns, relevant Lao/English content is consistent, local assets and routes resolve correctly, validation has been run at the appropriate level, and any remaining baseline issue is clearly reported.
